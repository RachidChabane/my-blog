## Owner manual steps (pre-launch)

These are the ONLY steps that cannot be automated. Complete them in order.
Everything else runs without secrets in CI.

- [ ] **Cloudflare account** — create a free account at cloudflare.com if not already done.
- [ ] **Cloudflare Pages project** — create a project named `my-blog` (Dashboard → Pages → Create a project → Connect to Git or Direct Upload).
- [ ] **`CLOUDFLARE_API_TOKEN`** — create an API token with *Cloudflare Pages: Edit* permission (My Profile → API Tokens). Add it as a GitHub Actions secret named `CLOUDFLARE_API_TOKEN`.
- [ ] **`CLOUDFLARE_ACCOUNT_ID`** — visible in the Cloudflare dashboard sidebar. Add it as `CLOUDFLARE_ACCOUNT_ID` GitHub Actions secret.
- [ ] **`OPENROUTER_API_KEY`** — create a key at openrouter.ai. Add it as a Cloudflare Pages environment variable named `OPENROUTER_API_KEY`.
- [ ] **`EMBEDDINGS_API_KEY`** — create a key for the chosen multilingual embeddings provider (OpenRouter or dedicated). Add it as Cloudflare Pages environment variable `EMBEDDINGS_API_KEY`.
- [ ] **`SITE_URL`** — set the live domain (e.g. `https://rachidchabane.dev`) as Cloudflare Pages environment variable.
- [ ] **Domain** — register `rachidchabane.*` and point its DNS CNAME to the `*.pages.dev` deployment URL (Cloudflare Pages → Custom domains).
- [ ] **tmux/subscription login** — on the owner's runner machine, run `claude` once interactively in a tmux window to authenticate the subscription session. The pipeline schedule (`pipeline/schedule/cron.py`) drives Claude on this session.
- [ ] **Cron install** — copy `pipeline/schedule/scheduler.cron.example` → crontab (`crontab -e`) and `pipeline/schedule/scheduler.plist.example` → `~/Library/LaunchAgents/` (macOS launchd alternative). Choose one and enable it.
